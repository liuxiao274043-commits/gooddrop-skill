# 照片 → 扫描件（photo2scan）

把「拍摄的纸质文档照片」还原成「扫描件」：纸张四角定位 → 透视校正 → 光照归一化（去阴影）→ 表格外框拉直 → 表单底纹还原 → 墨迹渲染（黑白 / 灰度）→ 输出 A4 PDF/PNG。

## 运行环境

- Python（已装好依赖，勿重复安装）：
  `/Users/CC/.workbuddy/binaries/python/envs/default/bin/python`
- 依赖：`opencv-python-headless`、`numpy`、`pillow`（缺了就 `pip install` 到同一个 venv，**不要**装到系统环境）

## 用法

```bash
PY=/Users/CC/.workbuddy/binaries/python/envs/default/bin/python
SCRIPT=/Users/CC/.workbuddy/skills/photo-to-scan/scripts/photo2scan.py

# 最常用：一张照片 → 主稿（黑白或灰度，自动判） + 彩色 两套 PDF/PNG
$PY $SCRIPT -i 照片.jpg -o 输出目录 -n 文档名

# 只要主稿
$PY $SCRIPT -i 照片.jpg -o out -n 合同 --mode main

# 小字密排的整页表格：强制灰度，可读性最好
$PY $SCRIPT -i 照片.jpg -o out -n 面谈表 --tone gray

# 大字号文档：强制纯黑白
$PY $SCRIPT -i 照片.jpg -o out -n 通知 --tone bw

# 多张照片 → 合成一个多页 PDF（按文件名排序）
$PY $SCRIPT -i "photos/*.jpg" -o out -n 合同

# 纸张定位不准时，手工给四角（左上 右上 右下 左下，像素坐标）
$PY $SCRIPT -i a.jpg -o out --corners "120,80 1180,40 1345,1775 60,1810"
```

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-i/--input` | 必填 | 照片路径，可多个、可通配 |
| `-o/--output` | `.` | 输出目录 |
| `-n/--name` | 首张照片名 | 输出文件名前缀 |
| `--mode` | `both` | 输出哪些文件：`both`（主稿+彩色）/ `main`（只出主稿）/ `color`（只出彩色）。`bw`、`gray` 是 `main` 的旧写法别名 |
| `--tone` | `auto` | 主稿墨迹渲染：`auto`（按正文字号自动选，见下）/ `bw`（硬二值纯黑白）/ `gray`（保色调灰度）。**`--tone auto` 判据：正文字高中位 < 2.8mm（≈8pt）就选灰度**——小字硬二值会把笔画削断 |
| `--paper` | `a4` | `a4` / `letter` / `a5` / `auto`。**中文办公文档几乎都是 A4，默认 A4**；`auto` 是「按四边形长宽比猜」，纸张定位有偏差时会横纵判反，一般别用 |
| `--dpi` | `200` | A4@200dpi = 1654×2339。所有像素级参数会按 `dpi/200` 同步缩放，所以 150~400 之间换 DPI 结果一致（已实测） |
| `--straighten` | `auto` | `auto`（自动判断）/ `on`（强制）/ `off` |
| `--shading` | `auto` | 表单底纹还原：`auto` / `on` / `off`。**要真彩色底纹就别关** |
| `--corners` | 无 | 手工四角，仅单张可用 |
| `--no-crop` | 关 | 不裁纸张，整图即文档 |
| `--k` | `0.18` | Sauvola k，**调大 → 笔画变细**。0.18 是小字密排稿的通用值；原稿字大笔画粗/底噪多/网点稿 → 0.22~0.30；小字笔画仍偏断 → 0.14~0.16 |
| `--win` | `61` | Sauvola 窗口（原图尺度像素） |
| `--ss` | `2` | 二值化超采样倍数 |
| `--min-area` | `40` | 删碎点（SS 域内的面积） |
| `--max-hole` | `110` | 补笔画小孔（SS 域内的面积） |
| `--debug` | 关 | 额外输出中间过程图到 `输出目录/_debug/` |

### 输出

主稿按实际渲染方式命名：`<name>_扫描件_黑白.pdf/.png` 或 `<name>_扫描件_灰度.pdf/.png`；彩色版固定 `<name>_扫描件_彩色.pdf/.png`。多张照片自动合成多页 PDF（按文件名排序）。

## 七步流程（`scripts/photo2scan.py`）

1. **纸张定位** —— 多策略候选：Lab 的 `b*` 通道（纸偏蓝、木地板/桌面偏黄；**纸与背景亮度接近时这是唯一有效判据**）、亮+低饱和、Otsu 亮区、去光照+Otsu。每个候选过「面积占比 / 亮度比 / 最小边 / **四边是否贴合真实图像边缘**」四道关，再按面积×亮度比×边支撑打分选优。
2. **亚像素吸附 + 透视校正** —— 沿边采样、法向灰度梯度峰值 + 抛物线插值 → 拟合直线 → 相邻边求交，迭代收敛到精确四角；再 `getPerspectiveTransform` 到 A4。
3. **光照归一化** —— **只用「纸面像素」**（判据：不比局部中位暗 8 级）做归一化卷积 `GaussianBlur(g·m)/GaussianBlur(m)` 估背景场并相除，把纸面拉到 `LEVEL=232`。阴影、渐晕、侧光一次消掉。
4. **表格拉直** —— 方向性形态学开运算滤掉文字 → 找长直线 → **两级跟踪**测线心 → **高斯平滑曲线**（`make_curve`，域内平滑、域外线性外推）→ `cv2.remap` 双向插值把弯曲的框线拉直。
5. **底纹还原** —— 检出大片淡灰打印底色（表单 `转正申请表` 那种格子底色），按实测灰度重绘；纸面纯白、底纹保持淡灰。**这是「原件扫描感」的关键，不要关。**
6. **墨迹渲染（两条路线）** —— 先算两种覆盖率：
   - **`bw` 硬二值**：2 倍超采样 Sauvola 局部阈值再降采样 → 抗锯齿黑白边缘；`clean_binary` 删碎点 + 补笔画小孔。大字号文档最干净。
   - **`gray` 保色调灰度**：`tone_cover` 用「局部纸面基准 − 该像素」算覆盖率，过 LO/HI 软膝（<0.16 纯白、>0.85 实黑）后线性过渡。**保留笔画边缘的中间灰度 → 笔画不断、字腔不空**，小字可读性远好于硬二值。
   `--tone auto` 按正文字号（去掉长直线后连通域高度的中位）选：< 2.8mm 用灰度。
7. **输出** —— 主稿（黑白/灰度）+ 彩色，各出 PNG + 多页 PDF。

## 关键坑（血泪教训，改动代码前务必读）

- **纸张定位：别只靠亮度**。白纸放在浅色桌面上时，亮度和 Otsu 都分不开；Lab 的 `b*` 通道才有区分度。反过来，木地板/深色背景上 `b*` 也有效。所以要**多策略候选 + 打分**，不要赌单一判据。
- **`S < percentile(S,60)` 在接近无色的图像上恒为假**（分位数为 0），会让「亮+低饱和」判据整幅失效。必须写 `<=`。
- **形态学开运算的核不能太长**：长核要求线在整段窗口内连续变黑，框线一旦弯曲就被打断，`span` 骤降。所以**不能只靠 span 门限卡框线**（分组正确时真框线 span 也就 0.85~0.91，一旦分组出错会掉到 0.44~0.58），**真正区分「框线 vs 文字行」的是强度门限** `RULE_MIN_STRENGTH`（原照片框线 17~27，文字行下划线 2~8，门限取 12）。合成表单框线强度可达 150+。
- **弯曲的粗框线会被「行分组」拆成两段，span 腰斩**（`RULE_GROUP_GAP`）。`_rules` 是先在「行长之和」上找峰、再取该段行区间算 span；一条弯线中间几行响应弱，于是断成 2239~2242（span 0.47）和 2247~2250（span 0.44）两段，**两段都过不了 0.50 门限 → 整条底框被丢弃** → 网格模型的下边锚到上一根线（y=2021）上，页面底部靠外推 → 底框残留 6.5px 波弯。`RULE_GROUP_GAP = 0.004 × 页长边`（最小 4 行）把这两段合并成一条 span 0.89 的线，问题消失。
- **拉直用的曲线必须「域内平滑 + 域外线性外推」，不能用高阶多项式**（`make_curve`）。跟踪域是页面两端各留 1.2% 边距（线本身只到 x=106..1598），但 `remap` 要在这之外继续求值：deg=6 太僵（域内残差 rms 1.21px → 拉直后仍残留 4.5px 波弯），deg≥8 域内很准但**域外会爆炸**（实测 deg=10 时 x=0 处偏出 500px、deg=16 偏出 1400px，直接把整页拉歪）。正确做法：把跟踪点按 1px 栅格重采样 + 高斯平滑（σ=3px），域外按端点斜率线性外推。
- **跟踪线心要用「固定窄窗 + 暗度加权质心」，不能用「连续跟踪」**：连续跟踪会顺着纹理漂到文字上。而且**必须双向跟踪**（从中点分别向两端），单向跟踪的误差会累积。
- **拉直要在「暗度图」上二次跟踪**：长核开运算在弯曲段把框线打断，只用它的响应去拟合，页面两端就没有实测点、只能靠外推 → 两端残余弧弯 20px 拉不平。二次跟踪在暗度图上用固定窄窗沿全宽跟线心，把两端真正跟住。
- **量直线度的窗口要比拉直更窄、阈值更高**（`win=8, thr=0.8` + 中值平滑）：否则质心会被线旁文字的淡墨尾巴带偏，读出假的大弯曲量。
- **补笔画小孔必须限制最大面积**（`MAX_HOLE`），否则 `floodFill` 会把表格框内部当成一个大洞整片填成墨（墨占比 8% → 63%）。
- **★ 小字文档别硬二值**。原照片纸面只有约 132 DPI（纸宽 1094px / 210mm），正文小字只有 15px 高。硬二值化把笔画削成锯齿、字不成形（「熟悉程度」变碎、「目前」变「日前」），但在同样条件下**灰度渲染完全可读**。判据就看脚本打印的「正文高 x.x mm」：< 2.8mm 一律走灰度。
- **★ 灰度渲染的纸面基准必须取「局部」，不能用全局 `LEVEL`**。纸面自身有慢变化（页边渐晕、纸纹），印刷底纹更是一整片暗区。用全局基准会把它们当成淡墨压成灰 —— 实测底纹格 234 → 219（颜色变了，就不是原件扫描感了）、页边多出一圈灰带（12px 环带非白 6582 个）。局部基准用 `paper_pixels`（排除笔画）平滑得到（σ≈20px，随 DPI 缩放），只跟随纸面慢变化。改完底纹 234 → 234、环带 → 0。
- **★ 所有「绝对像素」参数必须随 `--dpi` 缩放**（`SCALE = dpi/200`，`px()` 取奇数、`pxf()` 取浮点）。Sauvola 窗口、形态学核、高斯尺度、碎点面积都是按 200 DPI 调的；不缩放的话 300 DPI 量出的字高只有 200 DPI 的 0.79 倍，判据直接失效。**但作用在「源图」上的核（`_quad_from_mask`、`fallback_rect`）不能缩放** —— 源图分辨率是固定的，跟着输出 DPI 放大反而会把定位搞坏（实测 400 DPI 时纸张候选全部被否决）。
- **★ OpenCV 5.0 的 8U `medianBlur` 在大核上是「数据相关」的**：同一个 ksize，随机图能过，真实照片报 `(-215) k < 16 in function 'medianBlur_8u_O1'`。别赌，统一走 `median_big()`（≤15 直接调，报错就退化「降采样→小核中值→升采样」，等效窗口不变）。
- **float32 的 `medianBlur` 只支持 ksize ≤ 5**。一维序列的中值平滑（跟踪结果去毛刺）用 `median_flat()`，大核走滑窗 `nanmedian`。
- **默认 `k` 要照顾「小字密排」的原稿**：手机拍的整页表格，正文小字只有十几个像素高，Sauvola 阈值偏严会把笔画削成细线甚至断成空心字。实测 `k=0.22` 比 `k=0.18` 少 5% 墨量、字腔发空；`k=0.18` 在 5 张测试图上均无碎点、笔画完整，故取 0.18 为默认。判据：把正文区裁出来放大看，笔画应是实心的。
- **底纹检测的背景基准要用大窗中值**（`medianBlur`，窗宽≈0.105×长边），不能用闭运算 —— 闭运算的局部极大值会被 JPEG 振铃/渐晕抬高。
- **底纹的「纸面像素」判据要收紧到 `g > 0.90×基准`**：用 0.6 倍会把文字抗锯齿边缘算进来，密集文字行会被整行误判成底纹。
- **贴页面边缘的暗块是纸张边缘渐晕，不是印刷底纹**：连通域要排除贴边的（1.2% 边距内），并加面积上限 `SHADE_MAX_FRAC` 兜底（超过 50% 页面积判为光照残留，宁可不做）。
- **`cv2.medianBlur` 核有上限**（本机 OpenCV 5.0 实测可到 401），代码里 `clip(..., 31, 351)` 保底，不要盲目加大。
- **定位失败别硬裁**：错误的四边形会裁掉正文。宁可退化为「整图缩放」+ 兜底外接矩形 + 边缘中灰涂白，也不要按错误的角点裁。
- **纸张四角候选必须验「四边是否贴真实边缘」**：只按亮度/色度分割，在「纸有阴影」时会把阴影边界当纸边，切掉一个角。`quad_edge_support` 用「沿边采样、法向 ±13px 内有没有强梯度」判每条边，支撑 <0.25 直接弃用该候选。

## 验收指标（每次跑完看这几行）

脚本会自动打印：

- **墨迹占比** —— 通常 4%~12%；突然 >30% 说明补孔失控或二值化阈值不对
- **纸面纯白率** —— 目标 >85%
- **各区域纸面均值** —— 目标 ≥250（越低说明光照归一化没吃干净）
- **底纹区实测灰度 vs 目标** —— 两者应一致（如 234 / 234）
- **页面四周 12px 环带非白像素** —— 目标 0（>100 说明边缘残留背景/渐晕）
- **渲染方式（黑白/灰度）+ 正文高（mm）** —— 看是否合意；< 2.8mm 应自动走灰度，若被自动判成黑白且文字发碎，加 `--tone gray`
- **外框直线度（px）** —— 拉直后应 ≤1.5px（好的照片能到 ≤1.2px）；>3px 说明拟合没跟住框线，>10px 说明根本没拉直或被文字带偏
- **对照**：同一张图加 `--straighten off` 再看一次直线度，差距就是拉直的收益（例：新照片 上 5.47→0.61 / 下 13.46→1.02 / 左 3.48→1.03 / 右 6.18→1.17）

## 已知限制

- 纸张几乎占满整个画面、且**放在与纸亮度接近的无色桌面**上、又有强阴影切角时，四角定位可能失败 → 会走「亮区外接矩形兜底裁剪 + 边缘中灰涂白」，结果可读、干净，但纸边界可能残留一条极淡的虚线。
- `--paper auto` 依赖四边形的长宽比，定位有偏差时会横纵判反；中文文档请用默认 `a4`。
- 彩色版是「逐通道光照归一化 + 墨迹保留原色调」，彩章/彩印会保留；纯黑白文档彩色版看起来和黑白版一样，属正常。

## 调参速查

| 现象 | 处理 |
|---|---|
| 纸张没定位出来 / 定位歪了 | 先用 `--debug` 看 `_1_warp.png`；不准就 `--corners` 手工给四角 |
| **文字发碎 / 小字看不清 / 字腔发空** | 首选 `--tone gray`（保色调灰度，笔画连续）。这是小字密排稿的标准解法，比调 `--k` 有效得多 |
| 黑白模式文字太细 / 断笔 | 调小 `--k`（如 0.16~0.18）；小字密排稿尤其明显，0.22 会把笔画削断 |
| 灰度模式下字太浅 | 调低 `--tone-ink`（默认 130，越小越黑）、调低 `--tone-lo`（默认 0.16） |
| 灰度模式下页边/底纹发灰 | 检查局部纸面基准有没有生效（`tone_cover` 的 `ref` 必须来自 `paper_pixels`，不能是常数 `LEVEL`） |
| 底噪多 / 网点糊成一片 | 调大 `--k`（如 0.24~0.34）、调大 `--min-area` |
| 表格框线断成虚线 | 调小 `--k`、调大 `--max-hole` |
| 表单底纹被抹掉了 | 别加 `--shading off`；确认没被误判为光照残留（看日志的「检出底纹 …% 页面积」） |
| 页面边缘有灰边 | 看「12px 环带」读数；若是贴边暗块误判成底纹，检查 `SHADE_MAX_FRAC` |
| 表格框还是弯的 | 看「候选框线」条数是否 ≥2 横 ≥2 竖；被 `RULE_MIN_STRENGTH` 挡掉就适当降低 |
| 外框明显变直了但底部/右侧还差几 px | 检查该边有没有被 `RULE_MIN_SPAN` 挡掉（日志的「候选框线」里少一根）；是 `RULE_GROUP_GAP` 太小把弯线拆成两段，适当调大 |
| 拉直后页面被拉歪/比例失真 | 说明曲线在跟踪域外发散；确认 `make_curve` 的线性外推在执行（别改回高阶多项式） |
